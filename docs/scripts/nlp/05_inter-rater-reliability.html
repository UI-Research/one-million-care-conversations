Inter-rater reliability: Bree’s coding and the model coding

Author

Manuel Alcalá Kovalski, Urban Institute

Published

October 27, 2026

The plan for the open-ended answers and the interview transcripts is that a language model applies Bree’s codebook to everything, and Bree codes a random sample by hand to check it. This page is the first of those checks. It compares Bree’s coding of the answers in her September sample with two model runs from October 6, one by Claude Sonnet 5 and one by Claude Opus 5.5. All data presented in this document are preliminary and not for publication or dissemination.

Inter-rater reliability usually describes two trained people coding the same material. Here one of the two raters is a model and Bree is the reference, so the numbers say how closely each model reproduces her coding. How closely two people would agree is not measured yet; that needs a second person to code the same answers.

What Bree coded

Bree drew a random 15 percent of the data delivered by September 22, which came to one survey file, one canvassing file, and two interviews, and coded the survey and canvassing files in NVivo. Her coding log on Box marks the files she has finished and the codebook version she used:

Matching her coding to the answers

Keeping the comparison like for like

  • Same answers: only the answers Bree coded are compared.
  • Same list of codes: Bree used codebook version 5 (145 codes) and the models used version 6, which adds 22 codes and renames none. The models’ uses of the new codes are set aside (table below), so every coder chooses from the same 145 codes.
  • Same unit: one answer. A code counts once per answer, however many passages of the answer it was applied to.
  • Same domains: every code is placed in its version 6 domain for all three coders. No code changed domain between versions.
  • Still open: what gets coded. The models are told to “assign every code whose definition the passage clearly meets,” including codes from different domains, such as who the person cares for or what has been hard. Whether Bree codes everything an answer mentions or only what responds to the question is a question for her. The domain table below shows how much of the difference this accounts for.

How closely the coders agree

Each table compares two coders on the 71 answers:

  • Identical codes: the share of answers where both chose exactly the same codes.
  • Average overlap: for each answer, the codes both chose divided by the codes either chose, averaged over answers. 1 means identical, 0 means nothing in common.
  • First coder’s codes the second also chose and the reverse: for Bree and a model, the first is the share of Bree’s codes the model found, the second the share of the model’s codes Bree also used.
  • Krippendorff’s alpha: agreement corrected for the agreement two coders would reach by chance, given how often each code is used. 1 is perfect agreement and 0 is no better than chance. When two coders choose different but overlapping sets of codes, the MASI distance gives partial credit (Passonneau 2006). Krippendorff (2004, Content Analysis, 2nd ed.) recommends relying on coding with alpha of at least 0.80 and treating 0.67 to 0.80 as enough only for tentative conclusions.

The brackets are 95 percent intervals from resampling the answers 2,000 times. With this few answers they are wide; differences between the two models that fall inside them are not meaningful.

The second table repeats the comparison one level up: instead of the exact codes, which domains (Desired Supports, Challenges, and so on) each coder used on the answer.

# share of codes in common: both empty counts as identical
jaccard <- function(a, b) {
  either <- union(a, b)
  if (length(either) == 0) return(1)
  length(intersect(a, b)) / length(either)
}

# distance between every pair of code sets, filled once so the bootstrap only
# indexes into it
distance_matrix <- function(sets, distance) {
  n <- length(sets)
  d <- matrix(0, n, n)
  for (i in seq_len(n - 1)) {
    for (j in (i + 1):n) d[i, j] <- d[j, i] <- distance(sets[[i]], sets[[j]])
  }
  d
}

# Krippendorff's alpha for two coders: 1 - observed / expected disagreement.
# `d` holds the first coder's sets, then the second's, so answer i is row i
# and row n + i. Observed: the two coders on the same answer. Expected: any
# two sets drawn from all the sets both coders produced.
alpha_from_distances <- function(d, idx) {
  n <- nrow(d) / 2
  pooled <- c(idx, n + idx)
  observed <- mean(d[cbind(idx, n + idx)])
  m <- length(pooled)
  expected <- sum(d[pooled, pooled]) / (m * (m - 1))
  1 - observed / expected
}

pair_agreement <- function(x, y) {
  per_answer <- tibble(
    identical = map2_lgl(x, y, setequal),
    overlap   = map2_dbl(x, y, jaccard),
    both      = lengths(map2(x, y, intersect)),
    n_x       = lengths(x),
    n_y       = lengths(y)
  )
  d <- distance_matrix(c(x, y), masi_distance)
  measures <- function(idx) {
    p <- per_answer[idx, ]
    c(
      "Identical codes" = mean(p$identical),
      "Average overlap" = mean(p$overlap),
      "First coder’s codes the second also chose" = sum(p$both) / sum(p$n_x),
      "Second coder’s codes the first also chose" = sum(p$both) / sum(p$n_y),
      "Krippendorff’s alpha (MASI)" = alpha_from_distances(d, idx)
    )
  }
  estimate <- measures(seq_len(nrow(per_answer)))
  boot <- replicate(n_boot, measures(sample(nrow(per_answer), replace = TRUE)))
  tibble(
    measure = names(estimate),
    estimate,
    low  = apply(boot, 1, quantile, 0.025, na.rm = TRUE),
    high = apply(boot, 1, quantile, 0.975, na.rm = TRUE)
  )
}

pairs <- list(c("Bree", "Sonnet"), c("Bree", "Opus"), c("Sonnet", "Opus"))

agreement_table <- function(sets) {
  map(pairs, \(p) pair_agreement(sets[[p[1]]], sets[[p[2]]]) |>
        mutate(pair = str_c(p[1], " and ", p[2]))) |>
    list_rbind() |>
    mutate(shown = case_when(
      is.na(estimate) ~ "not yet computed",
      str_detect(measure, "alpha|overlap") ~ sprintf("%.2f (%.2f–%.2f)", estimate, low, high),
      .default = sprintf("%.0f%% (%.0f–%.0f)", 100 * estimate, 100 * low, 100 * high)
    )) |>
    select(Measure = measure, pair, shown) |>
    pivot_wider(names_from = pair, values_from = shown)
}

Agreement code by code

Each code Bree used on at least five answers: how many answers each coder gave it, how many both did, and Cohen’s kappa for that code (1 is perfect agreement, 0 is no better than chance). With this few answers per code, these are a guide to where to look, not estimates to report.

Show code 
cohen_kappa <- function(x, y) {
  observed <- mean(x == y)
  expected <- mean(x) * mean(y) + mean(!x) * mean(!y)
  (observed - expected) / (1 - expected)
}

What this shows so far

  • Where Bree and the models code the same thing, they mostly agree. On child care, senior care, affordability, and care for everyone, kappa is above 0.6 for both models.
  • Two of Bree’s codes account for about half of what the models miss. Of the 58 codes Bree chose that Sonnet did not, 28 are NEED_HIGH_QUALITY_CARE or NEED_OTHER (Opus: 29 of 62). Bree uses NEED_HIGH_QUALITY_CARE for answers about pay and working conditions for caregivers, which the models code as SOLUTION_CAREGIVER_WAGES or SOLUTION_CAREGIVER_WORKFORCE_DEV. Version 6 adds NEED_CAREGIVER_JOB_QUALITY, which may be the code for these answers. Where Bree uses NEED_OTHER, the models usually find a specific code, such as NEED_DIRECT_FINANCIAL_ASSISTANCE for an answer that reads “Money.”
  • Most codes the models add come from domains Bree did not use on that answer. Of the 95 codes Sonnet chose that Bree did not, 70 are in such a domain, mostly Solutions and Challenges (Opus: 84 of 109). The models code what has been hard and what would fix it alongside the support the person asks for. This is the open question of what gets coded.
  • The two models agree with each other much more than either agrees with Bree, and Opus agrees with Bree no more than Sonnet does. The differences point to the instructions and the codebook more than to the choice of model.

Next steps:

  • Bree decides whether an answer is coded for everything it mentions or only for what responds to the question. If the latter, the coding prompt changes to match, and rerunning both models on these answers costs under a dollar.
  • Bree settles the boundary between Desired Supports and Solutions codes that describe the same thing, and when NEED_OTHER applies.
  • The next round samples answers within each question instead of whole files, so the survey questions with the most answers are covered. This round has 7 survey answers.
  • The interviews are added once Bree codes them. A second person coding the same answers would show how far two people agree, which is the standard the models should be held to.

show_codes <- function(sets, reference = NULL) {
  map2_chr(sets, reference %||% map(sets, \(s) character()), \(s, r) {
    if (length(s) == 0) return("(none)")
    s <- str_replace_all(s, "_", "_<wbr>")
    shared <- str_remove_all(s, "<wbr>") %in% r
    if_else(shared, str_c("<b>", s, "</b>"), s) |> str_c(collapse = "<br>")
  })
}
