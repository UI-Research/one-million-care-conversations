Cleaning the survey and canvassing data

Author

Manuel Alcalá Kovalski, Urban Institute

Published

September 22, 2026

Program that turns the raw survey and canvassing exports from Caring Across Generations into clean, analysis-ready files.

The raw exports arrive as Excel files in a Box folder. scripts/00_ingest-raw.R copies that folder to data/raw/Raw data backups/ exactly as it is on Box. This program reads that local copy, cleans it, and writes four files to data/processed/:

  • survey_clean.rds / .csv: one row per survey respondent
  • canvassing_clean.rds / .csv: one row per canvassing contact (original form)
  • canvassing_revised_clean.rds / .csv: one row per contact on the revised form (August 2026 on)
  • data-dictionary.csv: every column in those files, with the question and answer text it came from

The steps at a glance

  1. Find the files. Pick the survey and canvassing exports out of the Box mirror by their file names; set aside the test delivery, the open-text exports, and the pre-launch poll. Every file must be claimed by a rule.
  2. Rename the columns from full question text to short names (q1, q2a, age, …), checking that nothing is missing or unexpected.
  3. Check for personal information. Address columns must be empty.
  4. Split the choose-all-that-apply questions into one TRUE/FALSE column per answer, keeping “Other” text word for word.
  5. Put single-answer questions in order (income, age, and so on).
  6. Work out which set of questions each person was shown (their “pathway”) from their first answer, and check that they answered those questions and no others.
  7. Tidy the rest: IDs, timestamps, ZIP codes. Confirm no ID repeats.
  8. Do the same for canvassing, reusing the survey’s answer lists — once for the original form and once for the revised form introduced in August, which asks different questions.
  9. Write the clean files and a data dictionary describing every column.
Warnings in this document are expected

Every step checks its own work. If a delivery looks different from what we expect — a renamed column, an answer we have not seen before, a file no rule claims — the program stops and says why, rather than guessing. The fix is always to update the rule that failed, never to loosen the check.

Some checks warn instead of stopping; those warnings appear below marked with !. The known ones (paid care providers shown two sets of questions, ZIP+4 entries, one canvassing contact who answered questions without agreeing to continue) are expected. A new warning is the signal to investigate.

The live form does not match the questionnaire PDF

The wording in the live form differs from the official question documents in many places, and the export format itself has changed between deliveries. Answer text in this program comes from what we actually observe in the exports, not from the PDF, and we keep a running record of how the form really behaves as deliveries arrive.

Find the files to clean

The file names in the Box folder already tell us what each file is: which tool (surv or canv), the date range, the distribution channel (f1, f2, …), whether it holds closed-ended or open-text answers, and whether the responses are complete or partial. We select files by those name patterns and never rename anything by hand.

Not every file is cleaned here. The f0 files are the pre-launch test and are left out. The open-text exports and the pre-launch poll go to the text-analysis pipeline instead. Every file in the folder has to fall into one of three groups — cleaned here, deliberately set aside, or an error — so a new kind of delivery can never slip through unnoticed.

Give the columns short names

In the export, each column is named with the full question text. We map those to short names that follow the questionnaire’s numbering: q1 is the connection-to-care question, q2a/q3a/q4a are the current-caregiver questions, and so on through q6. Demographic columns get plain names such as age and hh_income.

The mapping is checked in both directions. A column in the export that we have no name for stops the program, and so does a column we expect but cannot find. A few columns are allowed to be missing because they come and go across deliveries (the empty address fields in the test delivery, and q4c, which the test delivery lacked).

The open-text questions (q5 and q7) are not in these files. They arrive in a separate export and are handled by the text-analysis pipeline.

form_varying <- c("address", "address2", "city", "state", "q4c")

# exports from Aug 2026 on label the timestamp column "Date submitted"
# instead of "Time"; same Excel serial values underneath
timestamp_aliases <- c("Time" = "Date submitted")

# the same export writes en-/em-dashes and curly apostrophes ("$25,000–$49,999",
# "Affordable — without ...", "I don’t") where every other export writes plain
# hyphens and straight quotes
normalize_punctuation <- \(x) str_replace_all(x, c("—" = "-", "–" = "-", "’" = "'", "‘" = "'"))

read_delivery <- function(path) {
  read_excel(path, col_types = "text") |>
    rename(any_of(timestamp_aliases)) |>
    mutate(across(everything(), \(x) na_if(str_trim(normalize_punctuation(x)), ""))) |> # whitespace-only cells -> NA
    rename_validated(col_map, optional = form_varying) |>
    mutate(delivery = basename(path))
}

survey <- survey_files |>
  map(read_delivery) |>
  bind_rows() |>
  mutate(
    # filenames are inconsistent about case ("F1")
    form_version    = str_to_lower(str_extract(delivery, regex("f\\d+", ignore_case = TRUE))),
    response_status = str_extract(delivery, "complete|partial")
  )

# the filename f0-exclusion and the parsed form_version must agree
if (any(survey$form_version == "f0")) {
  cli::cli_abort("f0 test rows slipped past the filename exclusion")
}

Check for personal information

No personal information

The data shared with Urban must contain no personal information. ZIP code is collected on purpose; street address is not. The export still carries address columns, which should always be empty. If they ever are not, the program stops here so the file can be raised with the team before anything else happens.

pii_cols <- intersect(c("address", "address2"), names(survey))
if (length(pii_cols) > 0) {
  if (any(!is.na(as.matrix(survey[pii_cols])))) {
    stop("Address fields are not empty — possible PII in the raw file. Do not proceed; flag to the team.")
  }
  survey <- select(survey, -all_of(pii_cols))
}

Split the choose-all-that-apply questions into one column per answer

Most survey questions let people choose more than one answer. The export stores all of a person’s choices in a single cell, usually separated by vertical bars, for example "Care is unaffordable|Other: my own words". One delivery (the July–August complete responses) separates them with commas instead, which is trickier because the answers themselves contain commas; for those cells we match the known answers one at a time from the start of the cell. Either way, the result is the same: each question is split into one TRUE/FALSE column per answer option. For the challenges question q2a, that means columns such as q2a_unaffordable and q2a_time_flex.

How to read the TRUE/FALSE columns

Each answer column holds one of three values:

  • TRUE: the person chose this answer
  • FALSE: the person saw the question and did not choose this answer
  • NA: the person never saw the question (the survey routed them past it) or left it blank

The share of people choosing an answer is simply the share of TRUE among the non-missing values.

“Other” works a little differently. It is a free-text box, and the export records it three ways: "Other: some text", a bare "Other" when the box was ticked but left empty, or occasionally the text alone. Anything that is not one of the known answers sets {question}_other to TRUE and is kept word for word in {question}_other_text. Those words are respondents’ own voices and feed the text analysis.

Two safeguards sit inside this step. If the same “other” text appears from three or more people, the program warns — repeated text usually means a new answer option was added to the form and needs to be added to our list. And when the form’s wording for an answer changes (as it did on August 19, 2026, for four options), both the old and the new wording are listed for that answer, so responses from before and after the change land in the same column.

A small demonstration on a made-up question with answers a through f shows how the pieces fit: "c | e" and the comma form "c, e" both get TRUE for c and e and FALSE for the rest; an “Other” with text sets the other flag and keeps the text; a blank row is NA throughout; and answer a accepts two wordings.

Work out each person’s pathway

The first question asks about a person’s connection to care, and the answer decides which questions they see next. There are five pathways: people giving or receiving care now (current), people who cared for someone in the past (past), people who expect to in the future (future), people who know someone who receives care (observer), and people with no connection (none). A person who ticks answers from more than one group is routed to the first that applies, in that order. We checked this against the data — for example, a person eligible for both past and future was shown only the past questions.

Check that people answered the questions for their pathway

Each pathway question should be answered by exactly the people on that pathway. For complete responses we check both ways: nobody on the pathway should have skipped the question, and nobody off it should have answered. Partial responses may stop early, so they are only flagged if they answered a question outside their pathway. Mismatches produce a warning rather than stopping the program, because they point to a routing or export question for the team rather than a cleaning error. The one known exception: paid care providers who also cared for someone in the past were shown two sets of questions.

pwalk(skip_rules, \(question, indicator, expected_pathway) {
  answered <- !is.na(survey[[indicator]])
  eligible <- survey$pathway %in% expected_pathway
  mismatch <- if_else(
    survey$response_status == "complete",
    xor(answered, eligible), # completes must answer exactly their pathway
    answered & !eligible     # partials may stop early, but not cross paths
  )
  n_bad <- sum(mismatch, na.rm = TRUE)
  if (n_bad > 0) {
    cli::cli_warn(
      "{question}: {n_bad} respondent{?s} answered or skipped against skip logic"
    )
  }
})

dictionary <- bind_rows(
  dict_options,
  dict_factors,
  tibble(column = "hard_text", question = unname(question_text["hard_text"]),
         option = "Free text, kept verbatim (revised canvassing form)")
) |>
  mutate(question = if_else(
    column == "pathway",
    "Derived from q1 (priority: current > past > future > observer > none)",
    question
  ))

write_csv(dictionary, here("data/processed/data-dictionary.csv"))
